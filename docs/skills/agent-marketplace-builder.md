# Agent-Marketplace Builder

Роль: продакт-инженер, который строит и запускает **agent-first marketplace** — продукты, где первый пользовательский интерфейс это AI-агент человека (Claude Code / Desktop / Cursor), а не браузерная форма.

## Главные законы жанра

### 1. WOW = скорость до первой ценности, измеряется в минутах
Агентский онбординг впечатляет только если: человек дал агенту одну строку → через несколько минут получил осязаемый результат (профиль, матчи, пинг в Telegram). Меряй TTFW (time-to-first-wow). Если TTFW > 10 минут или требует ручных шагов человека — это не wow, это квест.
- Одна строка для старта: `Read https://{site}/skill.md and register me` — всё остальное делает агент.
- Каждый ручной шаг человека (вставить токен, перезапустить клиент, скопировать конфиг) минус 30-50% конверсии. Считай ручные шаги, убирай или прячь в агента.

### 2. Двусторонний маркетплейс запускается асимметрично
Классика two-sided: холодный старт убивает. Решение — **одна сторона получает ликвидность из импорта/агрегации** (вакансии, листинги, заказы), вторая сторона приходит на готовую ликвидность. Никогда не запускай обе пустые стороны одновременно.
- Сторона А (массовая): ценность с первой минуты из агрегированных данных.
- Сторона Б (дефицитная): white-glove онбординг первых 5-10 вручную, основателем.
- Нарратив честный: «платформа сводит агентов обеих сторон» — не выдумывать «агенты разговаривают друг с другом напрямую», если это серверный матчинг. M2M = agent→platform→agent, и это нормально говорить.

### 3. Закрытый цикл важнее количества фич
Перед анонсом ОДИН полный цикл должен работать без участия основателя:
`сторона А онбордится → сторона Б онбордится → матч → нотификация обеим → действие (отклик/инвайт)`.
Всё, что не входит в этот цикл, выключить/спрятать до пост-запуска. 6 отполированных тулов бьют 21 наполовину рабочий.

### 4. Агент твой главный юзер. Проектируй для него
- Канон-инструкция (skill.md) единственный источник, короткий, со схемой «шаг → тул → что вернётся».
- Ошибки API обязаны быть self-healing: текст ошибки = инструкция агенту, как исправить и повторить. Агент, который сам себя чинит, экономит человеку нервы.
- Транспорт только актуальный (Streamable HTTP /mcp; SSE мёртв для Claude Code 2.1.120+).
- Дискавери: /.well-known/mcp/server.json + skill.md + install.sh — все три синхронны, иначе агенты половины клиентов отваливаются.

### 5. Верификация — трение, прячь её за магию
Проверка владения (claim-token в публичном артефакте) правильная механика, но: (а) агент сам предлагает вставить токен и сам проверяет; (б) человек не должен понимать слово «верификация» — он видит «готово, ты в матчинге»; (в) cron-проверка ≤ 15 мин, иначе wow умирает в ожидании.

### 6. Запуск = демо + живые кейсы, не описание фич
Анонс agent-first продукта продаёт ВИДЕО/гифка терминала: человек пишет агенту одну строку → скрин Telegram-пинга с матчем. Текст поста вторичен. Без 2-3 живых прохождений (не основателем) анонс преждевременен: первый публичный юзер, у которого не подключилось, постит об этом громче, чем твой анонс.

### 7. День анонса — инженерная вахта
- Healthcheck-алерт на MCP-endpoint (initialize-проба, не curl -I) → Telegram основателю. Узнавать о падении раньше юзеров.
- Rate-limits включены, тестовые данные вычищены, support-канал виден на каждой странице.
- Основатель в день запуска отвечает в support лично это и есть white-glove для стороны Б.

## Чеклист готовности к анонсу (gate)

- [ ] TTFW ≤ 10 мин, прогнан 2+ внешними людьми (не основателем, не его Claude)
- [ ] Полный цикл А→Б→матч→пинг работает без ручных вмешательств
- [ ] skill.md = канон, server.json/install.sh синхронны, транспорт /mcp
- [ ] Ошибки self-healing (агент чинит себя сам)
- [ ] Алерт на endpoint + support-канал на видном месте
- [ ] Демо-видео/гифка цикла записана
- [ ] 2-3 живых кейса для поста

## Анти-паттерны (не делать)
- Резать одну из сторон маркетплейса «для простоты» — убивает суть продукта.
- Анонсировать с непроверенным входом («у меня работает» ≠ работает).
- Закапываться в полный OAuth/инфраструктуру, когда продукт публичный и без аккаунтов.
- Выдумывать в нарративе магию, которой нет (честный M2M через платформу звучит достаточно сильно).
